# 版本演进史：1.0 → 10.0

这份文档记录「节奏伙伴」从原型到 10.0 的十个版本各自解决了什么问题、为什么那样解决、以及留下了什么代价。

它不是更新日志。[CHANGELOG](../CHANGELOG.md) 记的是"改了什么"，这里记的是**为什么**。

---

## 关于版本号

对外版本号是 **1.0 – 10.0**，一个大版本 = 一次功能定型。开发过程中的内部编号是 `V1.0` 与 `V2.0 – V2.10`（共 12 个）。
定版时做了两处合并：`V1.0`（原型）与 `V2.0`（打击垫）并成 **1.0**，`V2.2`（修菜单）与 `V2.3`（编辑与导出）并成 **3.0**，
其余一一对应。对照关系见文末[附录](#附录旧号对照)。

所有版本都在 2026-11-01 这一天之内完成 —— 这是一次高强度的连续迭代，不是长期维护的结果。

| 版本 | 旧号 | 主题 | 一句话 |
|---|---|---|---|
| [1.0](#10--能敲出声) | V1.0 + V2.0 | 能敲出声 | 从"只能看"到"能实时敲"，打击垫与力度感应 |
| [2.0](#20--音色不再是摆设) | V2.1 | 音色可换 | 康加、箱鼓、贝斯、和声垫开放音色位 |
| [3.0](#30--能改也能带走) | V2.2 + V2.3 | 编辑与导出 | 撤销、清轨、第一次能把编曲导出成文件 |
| [4.0](#40--不再依赖外部素材) | V2.4 | 内嵌采样 | 14 件 CC0 原声鼓进代码，摆脱素材依赖 |
| [5.0](#50--移调不再滋滋响) | V2.5 | 算法重写 | WSOLA 换成相位声码器，代价是速度慢 5 倍 |
| [6.0](#60--和弦走得更远) | V2.6 | 表现力扩容 | 七小节进行、布鲁斯、WAV 改 MIDI |
| [7.0](#70--音符有了长度) | V2.7 | 音符时值 | 鼓音不再是一律 39ms 的断头音 |
| [8.0](#80--手机上真的能点) | V2.8 | 窄屏分页 | 16 格挤不下，改成 2 拍一屏 |
| [9.0](#90--把加过头的东西退回来) | V2.9 | 反馈修复 | 撤掉自动跟页，修掉"关着的层还在闪" |
| [10.0](#100--第一个正式版) | V2.10 | 定版 | 和弦补齐八格，小范围试用后定为 10.0 |

## 1.0 — 能敲出声

**解决的问题**：原型的鼓机只能"格子亮起来、听个响"，没有任何实时演奏手段。练琴的人真正想要的是手上有东西可打。

**做了什么**

- 8 个打击垫，键位 `A S D F G H J K` 沿左手八度铺开，右手不用离开方向键
- 按住不动时按落点高度给力度（0.55–1.0）：靠下更响。鼠标和手指用同一套判定
- 打击垫的敲击可以写进步进，自动量化到上一格的时刻
- 每层可切左/中/右声像（`C / L20 / R20` 循环）
- swing 上限放宽，66–68 之间显示"三连"
- 6/8 拍号额外显示附点四分 BPM，避免和四分音符混淆
- TAP 满 4 下取中位数，抗单次误点

**判断依据**：力度用"落点高度"而不是"按住时长"——按住时长要求人掐时间，落点高度是打击垫在真机上唯一自然的表达。

**代价**：打击垫和格子共用同一个 pattern，所以敲一下会改掉编曲。这是刻意选的——写进去才是"能用的输入方式"，只发声的垫子练琴时用不上。

## 2.0 — 音色不再是摆设

**解决的问题**：康加、箱鼓、贝斯、和声垫这四层在 1.0 时只有一种声音，界面上的音色位是灰的，"能换音色"是假的。

**做了什么**

- 四层全部开放音色位，共 31 档
- 新增 **808 金属簇**：六个非谐波方波（2 / 3 / 4.16 / 5.43 / 6.79 / 8.21 倍频）+ 7kHz 高通
- 音色浮层改两列布局，长列表不再超出手机屏幕
- 逐件电平校正：拨片贝斯是锯齿波过饱和，峰值天然高一截，压回 0.72 才不削顶

**判断依据**：31 档不是凑数。同一件乐器在民谣和电子里要的是两种声音，只给一个音色等于把风格预设的差异化吃掉一半。

**代价**：档位一多，"哪个音色适合这首歌"变成用户自己要解决的问题。后来靠风格预设把常用组合固定下来，算是补上了。

## 3.0 — 能改，也能带走

**解决的问题**：两件事。一是音色菜单点开就关不掉（`.vpick[hidden]` 被 `.vpick.wide` 以同等特异性覆盖，`hidden` 属性失效）；二是排好的编曲出不去，只能开着网页听。

**做了什么**

- 加 `.vpick[hidden]{display:none !important}` 一劳永逸，并补足 5 种关闭方式：再点乐器名、点 ✕、滚动、点外部、`Esc`
- 触摸判定阈值 10px → 18px（手指比鼠标抖）
- 打开态加橙色高亮，明确"当前展开的是哪个"
- 每轨一键清空（轨道名右侧小 ✕）
- 单步撤销 `Ctrl+Z`，环形快照；换拍号 / 换风格 / 导入存档 / 点收藏会让撤销失效
- 第一次导出：`OfflineAudioContext` 离线渲染 WAV，可选 1/2/4/8/16 小节，48kHz / 16bit
- 导出前自动停播，峰值超 0.985 整体压缩，避免削顶

**代价**：撤销是单步的，不是历史栈。够用，但连续点错两下就救不回来。WAV 导出要跑一遍完整离线渲染，导 16 小节要等几秒，而且必须先停播——不停播会撞上实时那头的调度，卡出爆音。

## 4.0 — 不再依赖外部素材

**解决的问题**：合成鼓再怎么调参，底鼓的"肉"和军鼓的"沙"都做不出来。但要引采样就绕不开授权——大部分免版税素材包只授权"用于音乐作品"，不允许把音频文件打包进开源代码。

**做了什么**

- 内嵌 14 件 **SFXMint CC0** 原声鼓采样（base64，约 340KB），彻底摆脱外部依赖，且仍然单文件
- 新增强音镲 / 叮叮镲两行，归在鼓组层里省两行高度
- 逐件按**前 150ms RMS** 配平响度。不是峰值对齐——峰值对齐会让脚踩镲比军鼓还响
- 开镲被闭镲掐断（choke）从硬编码键名改为**同族判断**，新加的采样也能正确被掐
- 采样随机偏移 0–2.5ms + ±4% 增益，避免连续击打的机械感

**判断依据**：授权先于素材。筛选标准写在 [SAMPLE-SOURCES](SAMPLE-SOURCES.md) 里——只接受允许再分发音频文件本身的授权（CC0 / CC-BY / MIT）。

**代价**：文件从 256KB 涨到 609KB，一个 html 里躺着 340KB 的 base64。换来的是"双击就能用，不联网也有原声鼓"。

## 5.0 — 移调不再"滋滋"响

**解决的问题**：用户反馈——载入一首手碟伴奏、升降调之后，整首曲子"滋滋啦啦"，杂音特别大。这是全项目最大的一次技术改动。

**怎么定位的**

把 `wsolaStretch` / `resampleSinc` 抄到 Node 里脱开浏览器复现，再用 Python 算"移调传递函数"——处理后频谱除以原曲频谱，分频段看中位数与 IQR。
结论很清楚：**中位数只是音量，IQR 才是"滋滋"**。高频段 IQR 抖动 12dB，说明不是整体变暗，是相邻帧在打架。

数学上的原因：WSOLA 时间伸缩时相邻帧必须错开 `HS×(1/ratio−1)` 个采样，这个错位对不同频率造成的相位偏移量不同，高频累积到接近一整周就相干抵消。

扫了 8 组参数（相关窗、跳数、分数延迟、帧长、搜索范围）都不收敛，确认**调参无解**，是算法本质。

**做了什么**

- 换成**相位声码器**：STFT，2048 点窗 / hop 512 / Hann 窗，逐频点独立累积相位（`sp += om*hopS`）
- 移到 **Blob Worker** 里跑，主线程全程 60fps 不阻塞；Worker 不可用时自动退回 WSOLA
- 修**时间轴漂移**：合成位置固定取整每帧带 ≤0.5 采样误差，3750 帧累积 40ms，和鼓机错位。改为按帧序号算浮点位置取整，实测延迟 5.5ms
- 修**电平损失**：sinc 插值的吉布斯过冲让峰值到 1.53，旧的硬性峰值保护会整体衰减 −3.9dB（听着就是"变小声了"）。改为只对超过 0.85 的尖峰做 tanh 软膝，电平误差收到 +0.26dB
- 分段电平对齐：声码器的相干损失随素材密度变化，整曲一个增益会把安静段推爆，改按 0.5 秒分段 + 三点平滑
- 不停乐切换：处理期间照常播旧版本，算完 60ms 交叉淡化切过去，不再有几秒静音
- 修处理期间换文件的竞态，修 `clearMelody` 没释放 `melody.orig` 的内存泄漏

**实测**：12k–20kHz 的传递函数从 −3.4dB 修到 −0.9dB，电平 +0.26dB；处理 8.1 秒期间播放位置连续推进，主线程稳定 59.9fps。

**代价**：4 分钟的歌桌面端约 8 秒，手机估算 20–40 秒（旧 WSOLA 只要 1.5 秒）。这是相位声码器的固有成本，换来的是不糊。另外 ±6 半音时音色会明显发闷，界面上会提示。

## 6.0 — 和弦走得更远

**解决的问题**：三件事一起做。和弦进行只有四小节，一句长的主歌唱不完就得回头；节奏风格里缺布鲁斯这个大类；WAV 导出既慢又不通用。

**做了什么**

- 新增 `4536251` 与 `m4536251` 两套七小节进行。原有的六套四小节保持原样，两种长度混着用——`rootMidi` / `chordThird` / `chordName` 一直按进行自身的长度取模，不用改逻辑
- 自定义槽固定 7 格：点四小节预设进来会按原长度循环填满（`1564` → `1564 156`），不会在第 5 格突变成主和弦
- 新增**布鲁斯**风格（第 17 套）：底鼓 1 和"和"、军鼓 2/4、镲走直八分，风格自带 **66% 摇摆**把每拍后半推成三连——这才是 shuffle 的成因。其他风格不写摇摆量，保持用户自己拖到的位置
- **导出 WAV 改成导出 MIDI**：手拼 SMF（format 1 / PPQ 480），鼓 / 贝斯 / 和声垫分三轨，鼓走 GM 第 10 通道
  - 音符不再由离线渲染产生，而是取自新抽出的纯函数 `stepEvents()`——**和播放共用同一份逻辑**
  - 摇摆偏移按 tick 换算写进事件；速度、拍号（4/4、3/4、6/8）都写进 tempo 轨
  - 导出只需 1ms，**不用停播**
  - 删掉 `OfflineAudioContext` 离线渲染与 WAV 编码，约 110 行

**判断依据**：布鲁斯必须直八分。如果写成三连音再叠摇摆，就变成"三连上再加三连"，出来的是乱的；直八分 + 66% 摇摆刚好是 shuffle。

**代价**：不能导出成品音频了。要听成品得把 MIDI 拖进 DAW。这个取舍在 [README](../README.md#已知限制) 里写明了——加 MP3 编码器就得引库，破"单文件零依赖"。

## 7.0 — 音符有了长度

**解决的问题**：6.0 导出的 MIDI 里，每个鼓音固定 30 tick，96BPM 下只有 39 毫秒。拖进 DAW 换采样器音源，不管八分十六分都是一串断头音。

**做了什么**

- 鼓音时值改为可调：`到下一击的间隔 × 时值比例`，90% 是连奏、30% 是断奏
- 控制行新增「时值」滑杆（30%–100%，默认 90%），改它不用重铺格子，也不打断正在播的小节
- 网格里直接看得到：每格底边一条横线，长度就是这个音实际持续多久；跨到后面的格子标成延续格接着画，右端空出来的那截就是音停下的位置
- 导出的 MIDI 按同一个数写：十六分 108 tick、八分 216 tick、30% 时 72 tick

**判断依据**：视觉上刻意**不用整格填色**。九层一起看，整行会被填满，反倒看不出节奏型打在哪。底边一条线既能读出长度，又不遮挡格子本身。

**代价**：只影响鼓轨。贝斯本来按拍给长度（1.9 格）、和声垫按整小节，再乘这个比例只会让它们变短。实时播放也不受影响——鼓是打击乐，音色自然衰减（底鼓 0.44s）本来就比时值长，硬掐到时值只会把鼓掐死。

## 8.0 — 手机上真的能点

**解决的问题**：用户报"手机根本调不动"。实测 390 宽的手机一条轨道净宽只有 292px，16 格平分每格 **16.75px**，比指尖小得多；320 宽更糟，只有 12.38px，而且页面本身横向溢出 15px。

**先算了一笔账**：用户最初的提议是"每屏最多 4 小节"。但 4 小节 = 64 格，每格只剩 4.5px，比现状还差。**单位应该是"拍"，不是"小节"**：

| 一屏格数 | 单格宽 | 相当于 |
|---|---|---|
| 16 | 16.75px | 1 小节（改前） |
| 12 | 22px | 3 拍 |
| **8** | **34px** | **2 拍**（采用） |
| 4 | 68px | 1 拍 |

**做了什么**

- 窄屏分页，每屏 2 拍 8 格，格宽按屏宽算：390 宽 35px、320 宽 26px
- 网格顶上一条导航条，点左右半边翻页、也能按住滑块拖，左边标「第 1–2 拍」
- 3/4 是两拍一页（8 + 4），6/8 一大拍就是 6 格、所以一拍一页
- 格宽按"页内格数最多的一页"定一次、所有页共用——否则翻到只剩 4 格的页会突然变宽
- 分页只动视图：`state.pattern` 仍用绝对格号，MIDI 导出、铺拍笔刷、撤销全不受影响
- 顺带修掉 320 宽下的横向溢出

**判断依据**：没有做成"网格自由横向滚动"。网格区已经占用了横拖手势（按拍铺满整行），同一根手指同时表达两件事必然误触。滚动只能收进一条独立的导航条。

**代价**：一屏看不全了。16 格一眼看全是鼓机本来最有价值的地方，手机上只能牺牲。另外 7.0 做的横向时值延续线在页边界会断开。

## 9.0 — 把加过头的东西退回来

**解决的问题**：8.0 顺手加的"播放自动跟页"是个坏主意；用户还反馈"沙铃好像坏了"。

**做了什么**

- **撤掉自动跟页**。边听边调的时候，页面自己横移会把正准备点的那一格甩到屏幕外，跟着节奏点反而点空。导航条现在只由人操作
- 修掉"层明明关着，播放时格子还在闪"：`highlight()` 遍历所有轨道时没检查层开关，于是一层被关掉后格子照旧亮橙闪动却不发声。**这才是"沙铃坏了"的真正原因**——沙铃是最容易在无提示下被关掉的一层（点风格预设时，预设里没列出的层会被全部关掉，布鲁斯只开鼓组）
- 关层瞬间抹掉残留高亮；关掉的层整组去色（`grayscale(1)`），暖橙＝在响、灰＝没在响

**这次的两个教训**

1. **顺手加的功能往往比不做更糟**。自动跟页在纸面上是"刚需"，实际用起来是干扰。改版时先问一句"这个自动行为会不会打断用户手上的动作"。
2. **加完最后一层透明度，就能看出是不是过大了**。不要猜，量。

## 10.0 — 第一个正式版

**解决的问题**：用户反馈"和弦少了一个，应该是 8 个而不是 7 个"。7 格的 `4536251` 走完第七个和弦就回到开头，第八小节等于被截掉。

**做了什么**

- 和弦条 7 格 → **8 格**
- `4536251` 补成 **IV–V–iii–vi–ii–V–I–vi**，`m4536251` 补成 **iv–V–III–VII–ii–V–i–VI**
- 自定义槽 `CUSTOM_LEN` 跟着改成 8，四小节预设仍按原长度循环填满
- 老存档里的七格自定义进行自动循环补到第八格（第 8 格＝第 1 格），听感不突变
- 390 宽下每格从 44.6px 变成 38.6px，仍然点得准

**第 8 格为什么是 vi**

如果第 8 小节回到主和弦，整句听起来就收尾了，接不回开头的 IV；停在 vi 是半终止，从 Am 回到 F 很顺地进下一轮。这是流行歌里最常见的八小节走法。

**为什么定成 10.0**

在一轮小范围试用之后定的版。试用者反馈的问题（手机点不中、和弦少一格、沙铃"坏了"）都已修完，剩下的都是明确的取舍而非缺陷，够格作为第一个对外的大版本。

**代价**：完整循环从 7 小节变成 8 小节，导出 MIDI 时要选 8 小节才是完整一圈。

## 贯穿全程的三条主线

如果把十个版本按主题重新归拢，其实是三条线：

**一、声音的可信度**（1.0 → 2.0 → 4.0 → 5.0）
合成音色 → 音色档位 → 内嵌原声采样 → 移调引擎重写。
这条线的终点是"敢拿它当练习伴奏"，而不是"听着像个玩具"。

**二、手上能不能点准**（1.0 → 3.0 → 8.0）
打击垫 → 菜单与撤销 → 手机分页。
每一版都在修同一类问题：**手指比像素粗**。18px 的触摸阈值、34px 的格子宽度，都是被同一件事逼出来的。

**三、做出来的东西能不能带走**（3.0 → 6.0 → 7.0）
WAV → MIDI → 时值。
这条线的判断标准很实在：导出的东西在 DAW 里能不能直接用，而不是"文件能不能打开"。

## 被否掉的路

留下这些，是为了以后不再走一遍：

| 方案 | 否决原因 |
|---|---|
| 网格自由横向滚动 | 与"横拖铺满整行"手势冲突，同一根手指不可能同时表达两件事 |
| 每屏 4 小节 | 64 格摊下来每格 4.5px，比改前还窄。单位应是"拍" |
| 播放自动跟页 | 8.0 加过，9.0 撤掉。会打断正在进行的点击 |
| 继续调 WSOLA 参数 | 扫了 8 组参数都不收敛，是算法本质不是参数问题 |
| 导出 MP3 | 要引编码器库，破"单文件零依赖" |
| 导出 WAV 保留 | 要跑离线渲染，手机上慢且内存吃紧；MIDI 更通用 |
| 多轨录音 / song mode | 这是伴奏工具，不是 DAW。加进来会让主界面变复杂 |
| 整格填色表示时值 | 九层一起看整行会被填满，看不出节奏型打在哪 |
